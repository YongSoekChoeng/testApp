# 요구사항 및 영향도 검토 보고서

## 1. 검토 개요
- **대상 문서**: 00-request.md, 01-requirements.md, 02-impact.md
- **검토 목적**: 로그 조회 메뉴의 SQL 에러 수정 요구사항이 영향도 조사서에 누락 없이 반영되었는지, 설계 및 보안/안정성 관점에서 결함이 없는지 검토

## 2. 요구사항 충족 여부 (FR Verification)

| ID | 요구사항 명칭 | 판정 | 검토 의견 |
| :--- | :--- | :---: | :--- |
| FR-01 | 로그인 이력 조회 기능 수정 | **충족** | `loginHist.jsp` 및 관련 테이블(`tbsy_login_hist`)의 `seq` 컬럼 부재를 확인하였으며, `login_dtm`으로의 변경 계획이 반영됨. |
| FR-02 | 액션 로그 조회 기능 수정 | **충족** | `actionLog.jsp` 및 관련 테이블(`tbsy_action_log`)의 `seq` 컬럼 부재를 확인하였으며, `in_dtm`으로의 변경 계획이 반영됨. |
| FR-03 | 에러 로그 조회 기능 수정 | **충족** | `errorLog.jsp` 및 관련 테이블(`tbsy_error_log`)의 `seq` 컬럼 부재를 확인하였으며, `in_dtm`으로의 변경 계획이 반영됨. |

## 3. 상세 검토 결과 (Detailed Review)

### [설계 및 구현 일치성]
- **심각도(주요) | 파일: 02-impact.md (Section 3) | 문제 |** JSP 파일 내 `<input type="hidden" ... value="seq desc"/>`를 수정하는 방식은 정적 값만 변경할 뿐, Kendo UI Grid 등 프론트엔드 라이브러리가 동적으로 정렬 컬럼을 변경할 때 발생하는 에러를 근본적으로 해결하지 못할 가능성이 있음.
- **제안**: JSP의 hidden 필드 수정뿐만 아니라, Grid의 `sortable` 설정 시 서버로 전달되는 `sort_column` 파라미터가 실제 DB 컬럼명과 매핑되도록 프론트엔드 스크립트(JS) 로직 검토가 병행되어야 함.

### [보안 및 예외 처리]
- **심각도(경미) | 파일: 01-requirements.md (Section 2) | 문제 |** 요구사항에 "SQL 문법 오류로 인해 서비스 프로세스가 중단되지 않도록 예외 처리가 적절히 수행되어야 한다"고 명시되어 있으나, 영향도 조사서에는 이에 대한 구체적인 예외 처리 로직(Try-Catch 또는 Global Exception Handler) 변경 계획이 누락됨.
- **제안**: SQL 에러 발생 시 사용자에게 친절한 메시지를 제공하고 로그를 남기는 예외 처리 로직이 포함되어 있는지 확인 필요.

### [성능 및 데이터 정합성]
- **심각도(경미) | 파일: 02-impact.md (Section 6) | 문제 |** 정렬 컬럼을 `seq`에서 `in_dtm` 또는 `login_dtm`으로 변경할 경우, 해당 컬럼에 인덱스가 생성되어 있지 않다면 데이터 양 증가 시 성능 저하(Full Table Scan)가 발생할 수 있음.
- **제안**: 변경되는 정렬 컬럼(`in_dtm`, `login_dtm`)에 대한 인덱스 존재 여부를 확인하고, 필요 시 인덱스 추가 검토.

## 4. 종합 결론
- **결과**: **FAIL**
- **사유**: 요구사항(FR)은 충족하나, 영향도 조사서에서 **1) 프론트엔드 동적 정렬 로직에 대한 근본적 대응 미흡**, **2) 정렬 컬럼 변경에 따른 성능(인덱스) 영향도 검토 누락**, **3) 예외 처리 요구사항에 대한 구현 계획 미비**가 발견됨.
