# 요구사항 정의서: 로그 조회 메뉴 에러 수정

## 1. 배경/목적
- 테스트 메뉴(로그조회) 내 특정 메뉴(로그인이력, 액션로그, 에러로그) 호출 시 SQL 문법 오류로 인해 데이터 조회가 불가능한 현상을 해결한다.
- 에러 로그 조회 쿼리에서 존재하지 않는 컬럼(`seq`)을 정렬 기준으로 사용하고 있어 발생하는 `Unknown column 'seq' in 'order clause'` 오류를 수정한다.

## 2. 기능 요구사항 (FR)

### FR-01: 에러 로그 리스트 조회 기능 수정
- **Given**: 사용자가 '테스트 > 로그조회 > 에러로그' 메뉴에 접속하고, 조회 조건(회사코드, 기간 등)을 설정한다.
- **When**: 에러 로그 리스트 조회 버튼을 클릭한다.
- **Then**: `tbsy_error_log` 테이블을 조회할 때, 존재하지 않는 `seq` 컬럼 대신 유효한 컬럼(예: `in_dtm` 또는 테이블의 PK)을 기준으로 정렬하여 정상적으로 리스트가 출력되어야 한다.

### FR-02: 액션 로그 리스트 조회 기능 정상화
- **Given**: 사용자가 '테스트 > 로그조회 > 액션로그' 메뉴에 접속한다.
- **When**: 액션 로그 리스트를 조회한다.
- **Then**: 쿼리 내 정렬 조건이 유효한 컬럼을 사용하도록 수정되어 리스트가 정상적으로 조회되어야 한다. (에러 로그와 동일한 패턴의 오류 가능성 검토 필요)

### FR-03: 로그인 이력 리스트 조회 기능 정상화
- **Given**: 사용자가 '테스트 > 로그조회 > 로그인이력' 메뉴에 접속한다.
- **When**: 로그인 이력 리스트를 조회한다.
- **Then**: 쿼리 내 정렬 조건이 유효한 컬럼을 사용하도록 수정되어 리스트가 정상적으로 조회되어야 한다.

## 3. 비기능 요구사항
- **감사로그**: 로그 조회 시 발생하는 SQL 에러가 시스템 전체의 안정성에 영향을 주지 않도록 예외 처리가 적절히 이루어져야 한다.
- **성능**: 정렬 기준 변경 시 인덱스를 활용할 수 있는 컬럼을 사용하여 조회 성능 저하를 방지한다.

## 4. 범위 제외 항목 (Out of scope)
- 인사/조직 모듈(insa/org) 관련 기능 수정 (현재 프로젝트 범위 제외)
- 로그 데이터 자체의 정합성 검증

## 5. 확인 필요 질문
1. `selectErrorLogList` 쿼리에서 `seq` 대신 사용할 기본 정렬 기준 컬럼은 무엇입니까? (예: `in_dtm` 내림차순)
2. `selectActionLogList` 및 `selectLoginHistList` 쿼리에서도 `seq` 컬럼을 사용한 정렬 오류가 있는지 확인이 필요합니다. (현재 에러 로그 파일에는 `selectErrorLogList` 관련 오류만 명시되어 있음)
3. `tbsy_error_log` 테이블에 실제 `seq` 컬럼이 존재하지 않는 것이 확실합니까? (MySQL `AUTO_INCREMENT`로 설계되었다면 컬럼명은 다를 수 있음)
