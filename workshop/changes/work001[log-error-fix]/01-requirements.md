# 요구사항 정의서

## 배경/목적
- 로그 조회 메뉴(로그인이력, 액션로그, 에러로그)에서 데이터 조회 시 발생하는 SQL 문법 오류를 해결하여 정상적인 로그 조회가 가능하도록 함.

## 기능 요구사항
### FR-01: 에러 로그 리스트 조회 기능 수정
- **Given**: 사용자가 '테스트 > 로그조회 > 에러로그' 메뉴에서 로그 목록을 조회하려고 함.
- **When**: 에러 로그 리스트 조회 요청(`getErrorLogList.ajax`)이 발생하고, 정렬 조건으로 `seq` 컬럼이 전달됨.
- **Then**: SQL 쿼리 내의 `ORDER BY seq desc` 부분에서 `seq` 컬럼을 찾을 수 없어 발생하는 `Unknown column 'seq' in 'order clause'` 오류를 해결하여, 실제 존재하는 컬럼(예: `in_dtm` 또는 `id` 등)으로 정렬되거나 오류 없이 목록이 출력되어야 함.

### FR-02: 액션 로그 리스트 조회 기능 점검
- **Given**: 사용자가 '테스트 > 로그조회 > 액션로그' 메뉴에서 로그 목록을 조회하려고 함.
- **When**: 액션 로그 리스트 조회 요청(`getActionLogList.ajax`)이 발생함.
- **Then**: 에러 로그와 동일한 정렬 이슈가 있는지 확인하고, 정상적으로 목록이 조회되어야 함.

### FR-03: 로그인 이력 리스트 조회 기능 점검
- **Given**: 사용자가 '테스트 > 로그조회 > 로그인이력' 메뉴에서 로그 목록을 조회하려고 함.
- **When**: 로그인 이력 리스트 조회 요청(`getLoginHistList.ajax`)이 발생함.
- **Then**: 정렬 조건에 따른 SQL 오류 여부를 확인하고, 정상적으로 목록이 조회되어야 함.

## 비기능 요구사항
- **감사로그**: 로그 조회 시 발생하는 에러는 시스템의 안정성을 위해 적절히 핸들링되어야 하며, 사용자에게는 친절한 메시지를 제공해야 함.

## 범위 제외 항목 (Out of scope)
- 로그 데이터의 삭제 또는 수정 기능.
- 새로운 로그 테이블 생성.

## 확인 필요 질문
1. `tbsy_error_log` 테이블에서 `seq` 대신 정렬 기준으로 사용할 적절한 컬럼은 무엇입니까? (예: `in_dtm` 또는 PK 컬럼)
2. `tbsy_action_log` 및 `tbsy_login_hist` 테이블에서도 `seq` 컬럼을 사용하여 정렬을 시도하는지, 혹은 다른 정렬 기준을 사용해야 하는지 확인이 필요합니다.
3. 현재 에러 로그 쿼리(`selectErrorLogListSql`)에서 `seq`가 아닌 다른 정렬 기준을 적용할 때, 프론트엔드에서 전달하는 `sort_column` 파라미터 값의 매핑 규칙이 별도로 존재합니까?
